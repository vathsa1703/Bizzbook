Release Blockers — 9 found

These fail core, everyday workflows outright. In this reviewer's judgment, none of the audited modules should ship until these are resolved.

  1. Sale creation is blocked company-wide. Every company in the live DB has zero rows in branches; POST /api/sales hard-rejects the resulting global scope, and nothing in the frontend sends the branch header to work around it. backend/src/routes/sales.js — router.post('/')
  2. 85% of the product catalog invoices at 0% GST, silently. gst_hsn_master is empty, so rate lookup for any non-custom-GST product defaults to 0 — and 0 passes validation as a legal slab, so nothing errors. backend/src/services/gstEngine.js — enrichItems()
  3. Sales never decrement stock — and delete/edit assume they did. Creating a sale leaves inventory untouched; deleting or editing one then adds stock back for a decrement that never happened, inflating inventory on every cycle. backend/src/routes/sales.js — post('/'), delete('/:id'), put('/:id')
  4. Purchases never increment stock. A purchase records cost/GST correctly but never updates inventory — stock stayed at 50 after a +10 purchase. backend/src/routes/purchases.js — router.post('/')
  5. Any purchase with a supplier attached crashes. Queries a state_code column on suppliers that doesn't exist — 500 on every purchase where a supplier is set. backend/src/routes/purchases.js — router.post('/'), ~line 63
  6. The Suppliers page crashes on load for every user. ChevronRight is referenced but never imported; React throws, the error boundary swallows it into a blank "Something went wrong" screen. frontend/src/pages/Suppliers.jsx:202
  7. Editing a product can silently null out its other fields. The update writes every column unconditionally instead of using COALESCE, so any field omitted from a PATCH-style edit (e.g. HSN code, supplier) gets wiped. backend/src/routes/products.js — router.put('/:id')
  8. Marketing → Reports: half the tabs 500 outright. Executive/Campaign/Customer/Loyalty analytics query columns that don't exist in the current schema (created_at, start_date/end_date, type). backend/src/services/ReportsService.js
  9. Report CSV export produces a broken file. Rows/headers are joined with the literal two characters "n" instead of a newline — the download is one malformed line, not valid CSV. backend/src/services/ReportsService.js — generateExport(), ~line 293

FAILSale creation — blocked for every company

All 10 companies in the live DB have zero rows in branches. POST /api/sales hard-rejects when scope resolves to global (the default when no branch is configured and no X-Branch-ID header is sent), and the frontend never sends that header anywhere in the sales flow.
